## Session 3: the dead shell diagnosed (time not captured)

### What Got Done

- **Found why every [[Claude Code]] shell has failed since the rebuild.** On Windows, Claude Code
  runs its shell tool through Git Bash when Git for Windows is installed, and falls back to a
  PowerShell tool only when it isn't. It checks for `C:\Program Files\Git\bin\bash.exe` once, when
  a session starts. The rebuild had no Git until 09-16, so every session got the PowerShell
  fallback, and on this machine that fallback fails every command with exit 1 and no output. The
  old install had Git, which is why this never showed up before. Read from Claude Code's own code
  (version 2.1.270), not guessed.
- **The plugin hook errors have the same cause.** Hooks also run in Git Bash when it exists and in
  PowerShell when it doesn't, so bash-style plugin hooks were failing with PowerShell syntax errors
  at every session start and stop. The `python3` hooks that fire after Write and Edit fail for a
  separate reason: Python isn't installed yet.
- Ruled out along the way: the sandbox (not applied to commands on Windows), execution policy (the
  tool passes `-ExecutionPolicy Bypass` and never runs a script file), hooks as the blocker (all
  non-blocking, none attached to the shell tool), the `FREDY2~1` short temp path, and PATH (Git
  Bash is found by its fixed install path, so the desktop app's stale PATH doesn't matter).

### What's Still In Progress

- **Check it in a new session.** Detection only happens when a session starts, so this session
  and any others already open stay on the broken PowerShell tool. A new session should get a
  working Bash tool. If it doesn't, quit and relaunch the desktop app. If it still doesn't,
  setting `CLAUDE_CODE_USE_POWERSHELL_TOOL` to `0` in `.claude\settings.json` forces the Bash tool.
- Once that's confirmed, remove the dead-shell caveats from [[Vault backup]] and the
  `vault-backup-auto-push` memory.
- Why the PowerShell fallback itself fails is still unknown. The best lead is Claude Code's
  Windows shell launcher, which runs it through `cmd.exe` and sends all output to a file. It can be
  switched off with `CLAUDE_CODE_DISABLE_WINDOWS_SHELL_LAUNCHER`. That doesn't matter while Git
  is installed, so it's parked.
