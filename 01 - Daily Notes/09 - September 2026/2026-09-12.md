### What Got Done, part 4: diagnosed the USB dropouts properly

- Nathan asked how to fix the hub. Went to the event log instead of guessing, and the
  premise was wrong: **it was never "twice tonight".** `Ntfs` event 98 fires on every mount
  and carries an incrementing `HarddiskVolume` number. That number went **173 to 254 between
  01:01 and 02:51**, so `E:`, `F:` and `H:` were remounting together about **28 times in two
  hours**. Only two of them were noticed because only two landed on a file operation.
- **The decisive clue was when it did not drop:** zero remounts during the 7-minute robocopy
  and zero during the 11-minute DISM split. It fails at rest, not under load. A loose cable
  fails under load. That is the signature of power management.
- Confirmed **USB selective suspend was enabled** and **disk spindown was 30 minutes**.
- **Learned what this machine actually is: a Surface Pro 7+.** One USB-A port, one USB-C.
  Every drive hangs off daisy-chained Genesys Logic hubs because there is nowhere else to
  put them. The Seagate is genuine (`0BC2:331A`, UAS) sitting behind a Genesys SuperSpeed hub.
- **Corrected a claim made earlier tonight: `D:` is not an internal SSD.** It is a SanDisk
  SD7SB6S256G1122 enumerated as `USBSTOR`, behind a no-name ASMedia bridge with the fake
  serial `12345678934A`. `Program Files`, `Users` and `WindowsApps` are on a USB enclosure
  on the same tree that has been dropping out all night.
- **Applied the fix** from an elevated shell and read the settings back to verify: selective
  suspend disabled (AC and DC), disk spindown never (AC and DC), and the four power-down
  values zeroed on both root hubs, both Genesys hubs, the Seagate and the SanDisk bridge.
  Started a 25-minute idle watch to prove it rather than assume it.
- **Nathan said the tablet has a battery, which contradicted what the machine reports.** He
  was right and the machine is wrong. Chased it: `Surface Battery` is Code 45 ("not
  connected"), because **`Surface Serial Hub Driver` is Code 10 ("cannot start")**, and that
  bus is what carries the embedded controller that presents the battery. `Surface UEFI` and
  `Surface ME` are both Code 14, asking for a restart, so a firmware update is staged and
  unapplied.
- **That is a live data risk, not a cosmetic one.** With no visible battery Windows thinks it
  is on permanent mains: no low-battery warning, no graceful shutdown. Pull the charger and
  it stops dead, mid-write, with the programs drive and the 4 TB drive both on USB. That is
  how the 09-01 NTFS corruption happened.
