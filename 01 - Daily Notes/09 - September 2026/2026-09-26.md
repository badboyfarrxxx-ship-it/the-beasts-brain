## Session 2, 11:56 PM: Swipe to seek, live picture

### What Got Done
- Nathan tested build 3: the time bubble showed and the jump on release worked. He asked for two changes: see the picture move while dragging, and the faster the finger moves, the more time it covers.
- Changed the patch: the video now seeks live while dragging (at most every 100 ms, with a catch-up seek when the finger pauses). Each movement covers 30 s per screen width when slow, rising to 600 s per width for a fast flick, based on Qt's smoothed finger speed. A drag stops just short of the end so it can't end playback.
- A review caught five more problems (speed spikes from bunched touch events, a huge jump when scrubbing stops mid-drag, a wasted first seek, the picture lagging the bubble, a seek to the very end stopping playback); all fixed.
- Build run 4 passed in 24 min: https://github.com/badboyfarrxxx-ship-it/vlc-build/releases/tag/build-9e59d4b38-run4-a1

- Nathan tested run 4 on the Surface: it works (live picture while dragging, speed follows the finger).
- On the way, found 11 VLC processes stuck in the background from earlier test runs. They had no window, locked the old build's files, stopped new copies from opening, and couldn't be killed (stuck in Windows, likely the graphics driver). A restart cleared them.

- Tracked down the stuck-on-close problem. Tests ruled out hardware decoding, sound, graphics drawing, the media library, network scanners and the missing plugin cache (`plugins.dat`); even VLC left open 10 seconds and closed from PowerShell stayed stuck 20+ minutes. A minidump from Process Explorer showed the cause: after VLC shuts down, Windows unloads `libqt_plugin.dll`, and a Qt cleanup routine waits forever for a thread Windows has already stopped.
- Fix: `patches/0002-exit-without-dll-teardown.patch` makes `vlc.exe` end itself right after its normal shutdown (settings already saved), skipping the unload step. Build run 5 passed: https://github.com/badboyfarrxxx-ship-it/vlc-build/releases/tag/build-9e59d4b38-run5-a1

### What's Still In Progress
- Nathan to test run 5: VLC should be gone within seconds of closing.
- The zip ships without `plugins.dat`, so VLC scans all ~500 add-ons at every start (slower start). Running `vlc-cache-gen.exe plugins` once after unzipping creates it.
- The 30 s and 600 s speed figures can be tuned if Nathan wants.

### Decisions Made
- Reversed session 1's "jump on release" choice at Nathan's request. Seeks are limited to one per 100 ms so the Surface's decoder isn't flooded.
